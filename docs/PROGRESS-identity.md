### Authentication: what failed and what worked

- **OAuth 2.0 / JWT Bearer External Credential (failed).** Configured with identity provider `https://oauth2.googleapis.com/token`, iss and sub set to the service account email, aud set to the token URL, a custom `scope` claim, and the uploaded certificate. Every callout failed with "Unable to complete the JWT token exchange. Error: . Error description: ." (blank), status 0 in the debug log, even at Callout FINEST.
- First run failed earlier with "We couldn't access the credential(s)" until the permission set had External Credential Principal Access and Read on User External Credentials.
- **Isolating the cause.** The same certificate, claims, and scope succeeded through plain Apex (`Auth.JWT` + `Auth.JWS` + `Auth.JWTBearerTokenExchange`, via a temporary Remote Site Setting), returning status 200 and an access token. Adding `nbf` (the one default claim the External Credential sends that cannot be deleted) also succeeded. Changing or removing `kid` and adding or removing the credential-level Scope field made no difference. Conclusion: the Google side and the claims are correct; the failure is inside the External Credential's token exchange, which also discards Google's error response.
- **JWT protocol External Credential (works).** Switched to the External Credential "JWT" protocol, which sends a self-signed JWT directly to the API instead of exchanging it for a token. Claims: iss and sub set to the service account email, `aud = https://admin.googleapis.com/`, `kid` set to Google's key ID, no scope claim. Named Credential `Google_Directory_API_v2` with Generate Authorization Header on.
- Result: no token exchange, no token caching, no auth code. Each callout carries a fresh JWT valid for 120 seconds, signed with the non-exportable key.

## 2026-11-05: Phase 1 close-out (client, plumbing, live chain)

### GoogleDirectoryClient
- `GoogleDirectoryClient`, `DirectoryResult`, routed `DirectoryMock` (throws on any unplanned callout), 12 tests; coverage 95 to 98%. No DML in the client; logs are inserted by the caller after the last callout. Dry run skips writes only. Passwords and hash functions are redacted before logging.
- Live smoke test passed: create (200), group add by Google user ID (200), suspend and OU move in one patch (200), group remove by ID (204). Membership keys on the immutable user ID.
- `on` is reserved in Apex (as in `trigger X on Contact`); the mock method is `route()`.

### Event plumbing (plan-only)
- `ContactDirectoryTrigger` publishes `Directory_Sync_Request__e` when Lifecycle Status, Program, Term, or name changes. No queries, callouts, or jobs in the save path.
- `DirectorySyncRequestHandler` de-duplicates Contact IDs and enqueues one `DirectorySyncJob` each. Subscriber batch size lowered from 200 to 50 to match the per-transaction enqueue limit.
- `DirectorySyncPlanner` maps status to a target state (Active, Suspended, None) and decides CREATE, MOVE, REACTIVATE, SUSPEND, NONE, or ERROR. Unmapped statuses fail closed; more than one Google match is an error.
- `DirectorySyncJob` reads the Contact, looks it up in Google, and logs the plan. No writes to Google in Phase 1. `DirectorySyncFinalizer` logs unhandled failures and falls back to an unlinked row if the Contact link fails.
- Default settings: Enabled on, Dry Run on. 35 tests passing.

### Findings from the first live run
- **Private Contacts are invisible to the integration user.** A Contact with no Account is visible only to its owner. `without sharing` made the query work, but the log insert still failed with INSUFFICIENT_ACCESS_ON_CROSS_REFERENCE_ENTITY: lookups require the running user to see the referenced record, even in system mode.
- **Fix: Account-scoped sharing instead of a bypass.** Account OWD set to Private (Contact Controlled by Parent). New checkbox `Account.Directory_Sync_In_Scope__c`; criteria sharing rule Directory Sync Scope shares in-scope Accounts (read) and their Contacts (read/write) with the Directory Sync Integration group, whose only member is the integration user. `DirectorySyncJob` is back to `with sharing` with no system-mode query.
- **License-scoped grants:** Read on User External Credentials in `Google Directory Sync` (a standard permission set) did not take effect for the Integration-licensed user. The callout failed with "You don't have read permissions on the User External Credential object" until the grant was added to `Directory_Sync_Data_Access` (Salesforce API Integration license). Phase 1 Check 1 was a false pass: the assignment saved, but not every grant applied.
- Result: Contact edit, event, subscriber, and job all ran as Integration Directory Sync; Lookup returned 200 and the Plan logged CREATE, linked to the Contact.
- Removed `Google Directory Sync` from luke's own user. Only the integration user can call Google.
- **Finding:** Custom Metadata Types deployed from source get a page layout without their custom fields, so the Default record's edit page in Setup showed none of the settings. Added the fields to the layouts by hand (Setup > Custom Metadata Types > [type] > Page Layouts) for `Directory_Sync_Setting__mdt` and `Directory_Status_Mapping__mdt`, then retrieved both layouts into source so the next deploy carries them.
- **Finding:** with Contact set to Controlled by Parent, an Account sharing rule has no separate Contact access; Contacts inherit the Account access level. The rule's `contactAccessLevel` (Edit) was ignored, so the integration user got Read on Contacts and the first live create failed at the Contact write-back (INSUFFICIENT_ACCESS_OR_READONLY) after Google had already created the account. Fixed by setting the rule's Account access to Read/Write; the integration user's permission set still allows only Read on the Account object, so it cannot edit Accounts. Google-side work is not rolled back by a Salesforce failure, which is why the job looks up by Salesforce ID before any create.
## 2026-11-06: Phase 2 joiner path

- Normalizer: `UsernameNormalizer` builds first.last usernames (nicknames dropped, accents transliterated, apostrophes dropped, last-name spaces to hyphens, capped at 62 so a collision suffix fits in 64) and Unicode display names capped at 40. 20 name fixtures plus edge cases.
